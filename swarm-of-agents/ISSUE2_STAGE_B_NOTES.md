# Issue 2 — Stage B: Event-based awareness and response metrics

## Files in this bundle

- `swarm_simulation_dynamic.py` — event registry, affected-agent attribution, awareness and response timing, summary/JSON metrics.
- `agent_snn_v3.py` — explicit metadata on genuine planner events (`triggered_by_known_hazard`, `response_kind`); no synthetic plan events added.
- `dynamic_disaster_engine.py` — `DisasterEvent.edges_newly_disabled_ids` now records exact edge identities for engine-generated events.
- `test_dynamic_disaster.py` — six Stage B regression tests and an import-path correction so the local `swarm-of-agents` files are preferred over similarly named parent-folder modules.

## Metric definitions

1. A dynamic hazard event is registered when the disaster engine emits it during `run()`. IDs are unique within one simulation (`hazard_000001`, ...).
2. An agent is initially affected when an event node/edge intersects its active planner route or its current node/local adjacent neighbourhood at event time.
3. Awareness is recorded only when an agent actually observes a mapped hazard node, receives it in a teammate message, or successfully reads a teammate-published hazard node from shared memory. Global board visibility is not awareness.
4. Awareness time is the first recorded awareness step for that agent-event pair. Later duplicate reports do not overwrite it.
5. Planner response is event-linked only when a genuine `reason == "invalidated"` plan event includes a blocked route node mapped to an event that the agent had already become aware of. A successful planner response requires a replacement plan and a changed active route.
6. Default SNN response is reported as a `default_policy_safe_navigation_action` when its selected next hop avoids the event's mapped nodes/edges after awareness. This is explicitly descriptive, not proof that the hazard caused a route change.

## Important limitations

- The event engine previously exposed only an edge count. It now exposes exact newly-disabled edge IDs where generated by the built-in engine. For custom/legacy event providers, the simulation can use a graph diff only when one event occurs in that tick. Ambiguous simultaneous-event attribution is omitted rather than guessed.
- Initial step-0 mainshock is not counted as a dynamic event in this registry; this registry records events emitted during the simulation's dynamic `tick()` loop.
- `affected_agent_event_pairs` is an event-time exposure definition, not a claim that all affected agents necessarily know about the event.
- `awareness_outside_initial_affected_set` separately counts agents who receive event information but were not initially classified as affected.
- The default SNN policy is greedy one-hop navigation. Its safe action metric is not called a replan and does not establish causal adaptation.
- Planner response delay is measured from first recorded event awareness to the qualifying planner response. Failed or unchanged replans are retained as unsuccessful responses when event-linked.
